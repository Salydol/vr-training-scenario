# VR Training

Тестовое задание: VR тренажер со сценарием из групп шагов.

Unity 6000.6.8f1, URP, XR Interaction Toolkit 3.7.0, OpenXR.

## Как запустить

1. Открыть проект в Unity 6000.6.8f1
2. Открыть сцену `Assets/_Project/Scenes/Lobby.unity` и нажать Play
3. Если шлем не подключен, сам включится симулятор (XR Interaction Simulator), подсказки по клавишам он показывает в окне Game. Кнопки UI можно нажимать и просто мышкой

Перемещение: телепорт и скольжение стиками. Клик по объекту и взятие в руку делаются лучом контроллера.

## Что есть в проекте

- Лобби с меню и переходом в тренировку
- Сценарий «Смена на складе»: 3 группы по 3 шага, в шаге одно или несколько действий
- Действия: дойти до точки, взять объект, кликнуть лучом, нажать кнопку UI
- Ошибка в шаге, нарушение порядка (группа закрывается, незаконченные шаги помечаются пропущенными)
- Звуки правильно/ошибка (генерятся кодом), подсветка нужного объекта контуром
- Табло с текущей группой и статусами шагов, в конце панель итогов с кнопками «Попытаться ещё» и «Возврат в Лобби»

## Архитектура

Все системы общаются через свою шину событий `EventBus<T>` и друг про друга не знают, поэтому DI не нужен. Объекты на сцене (`ScenarioTarget` и наследники) только сообщают что игрок что то сделал: дошел, взял, кликнул, нажал. Правильно это или нет они не решают. Решает `ScenarioRunner`, это обычный C# класс без MonoBehaviour: он сравнивает действие с тем что ждет текущий шаг, ставит статусы и кидает события (шаг начался, шаг закончен, группа закрыта, сценарий закончен). На эти события подписаны UI, звук и подсветка, каждый занимается только своим делом.

Сам сценарий лежит в ассете `ScenarioData` (ScriptableObject): группы, шаги, действия с типом и id объекта. Чтобы сделать другой сценарий, код менять не надо, достаточно создать новый ассет и расставить объекты с нужными id. Новый тип действия добавляется наследником `ScenarioTarget`, новая подсветка через интерфейс `IHighlight`.

## Структура папок

```
Assets/_Project
  Data        ассет сценария
  Materials   материалы
  Prefabs     Core (игрок, системные объекты), Interactables, UI
  Scenes      Lobby, Training
  Scripts     Core/Events, Scenario, Interaction, Highlight, Audio, UI, SceneManagement, Player
  Shaders     шейдер контура
```

В `Assets/Samples` лежат стартовые ассеты от Unity (XR риг, экшены ввода, симулятор), сторонних ассетов нет.

## Как сделать систему сценариев еще гибче

Сейчас сценарий линейный: группы идут по очереди, шаги внутри группы тоже. Если развивать дальше, я бы сделал так:

- Шаг хранит не список действий, а условие завершения. Условия собираются из простых кусочков (сделал действие, прошло время, объект в нужной зоне) и объединяются через «и», «или», «по порядку». Тогда можно описывать шаги вроде «возьми любой из двух огнетушителей» без нового кода
- Вместо линейного списка граф: у шага есть переходы в зависимости от результата. Ошибся, значит уходишь в ветку с разбором ошибки, а не просто дальше
- Реакции на шаг (звук, подсветка, подсказка, включить объект) тоже описывать данными в самом шаге, а не зашивать в код
- Описание сценария хранить в JSON, чтобы методист мог править его без Unity, а в проекте его только загружать и проверять что все id объектов есть на сцене

Такой подход хорош тем что программист один раз пишет набор условий и реакций, а дальше сценарии собираются из них как из кубиков.
